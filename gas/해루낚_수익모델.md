# 해루낚 수익 모델 — 적용 현황

> 아래 구상 중 **코드로 이미 구현된 것**입니다. 데이터 파일(data/*.json)과 구글 시트만 만지면 영업이 굴러갑니다.

| 모델 | 구현 상태 | 운영 방법 |
|---|---|---|
| 지역 상권 제휴 | ✅ 상세 화면 「이 근처(제휴)」 — 낚시점·숙박·식당·낚싯배 카드, 전화·링크 버튼 | `data/partners.json` 에 업체 추가. 노출·클릭이 자동 집계됨 |
| 광고 슬롯 | ✅ 지역·월·모드 타겟팅, **금어기 대상 광고 자동 차단**, 일자별 순환 | `data/ads.json`. 프리미엄 사용자에겐 숨김 |
| 장비 제휴 | ✅ 그날 조건이 만든 필요에만 노출 (시야 나쁨→랜턴, 펄→장화, 추움→장갑) | `data/gear.json` 에 쿠팡파트너스 등 링크 |
| 선박 예약 중개 1단계 | ✅ 낚싯배 카드의 「예약 문의」 → 시트 「예약문의」 적재 + 주인 메일 알림. 레퍼럴 코드 동반 기록 | 접수 후 전화 연결. 결제는 아직 업체가 직접(안전) |
| 레퍼럴 수익분배 | ✅ ?ref= 귀속(30일) → **매월 1일 자동 정산**: 유입 규모로 분배율(30/35/40%) 산정, 시트 「정산」 기록 + 메일 | 유튜버에게 코드만 발급하면 끝 |
| 이용권(프리미엄) | ✅ 시트 「이용권」에서 코드 발급 → 사용자가 앱에서 등록 → 1년간 15일 전망 + 광고 제거 | 송금 안내는 `data/monetize.json` |
| 성과 집계 | ✅ 제휴·광고·장비·예약 노출/클릭이 업체 코드별로 쌓이고 월간 정산 메일에 포함 | 자동 |

**지키는 선(코드에 박음):** 안전 정보·경고는 어떤 경우에도 무료 · 금어기 대상 광고는 규정 재확인 후 차단 · 광고는 상세 화면 한 슬롯뿐.

**아직 안 한 것(의도):** 인앱 결제(전자금융 이슈 — 코드 판매로 우회), 예약 결제 대행(분쟁 리스크 — 문의 중개까지만).

# 해루낚 수익 모델 구상

「물때 해석을 대신해주는 앱」이라는 자리에서 자연스럽게 돈이 되는 지점만 골랐습니다.
사용자가 이미 하려던 행동에 얹는 것이 우선이고, 광고를 앞세우는 건 마지막입니다.

---

## 1. 선박 예약 중개 (말씀하신 것 — 가장 확실합니다)

**왜 되는가**
섬 포인트 165곳을 이미 갖고 있고, 각 지점에 출항지와 소요시간이 붙어 있습니다.
사용자가 "여기 가야겠다"고 결정한 **바로 그 화면**에서 배편이 필요해집니다.
검색해서 찾아 들어오는 예약 사이트보다 전환이 훨씬 높은 자리입니다.

**단계별로 나눠 접근**

| 단계 | 하는 일 | 수익 | 난이도 |
|---|---|---|---|
| 1단계 | 여객선 시간표·요금 정보 제공 + 예약처 연결 | 제휴 수수료 또는 없음 | 낮음 |
| 2단계 | 낚싯배(선상낚시) 가격 비교 — 출항지·대상어·인원별 | 예약 건당 5~10% | 중간 |
| 3단계 | 앱 안에서 결제까지 | 건당 8~12% | 높음 |

**낚싯배가 여객선보다 돈이 됩니다.** 여객선은 공영에 가깝고 수수료 여지가 적지만,
선상낚시는 1인 8~15만원에 예약 경로가 파편화되어 있습니다(전화·카페·개인 블로그).
"오늘 갈치 조황 좋은 배 어디" 를 앱이 답하고 바로 예약을 붙이면 선주도 사용자도 이득입니다.

**주의할 점**
- 출항 취소가 잦습니다(기상). 취소·환불 정책을 명확히 하지 않으면 분쟁이 그대로 앱 평판이 됩니다.
- 통신판매중개업 신고가 필요하고, 결제를 직접 받으면 전자금융업 이슈가 생깁니다.
  초기에는 **예약 신청만 중개하고 결제는 선주가** 받는 구조가 안전합니다.

---

## 2. 제가 추가로 제안하는 것 — 우선순위 순

### ① 조황 공유와 포인트 기여 (수익 전 단계, 그러나 가장 중요)
사용자가 조과를 올리면 그 데이터로 점수 가중치를 보정합니다.
**돈이 되는 건 나중이고, 이게 있어야 다른 앱이 못 따라옵니다.**
물때 계산은 누구나 베끼지만, "이 포인트에서 이 물때에 실제로 나왔다"는 기록은 못 베낍니다.
- 상위 기여자에게 무료 이용권·제휴 할인
- 쌓인 데이터가 곧 아래 모든 수익 모델의 근거가 됩니다

### ② 유료 구독 (월 3,000~5,000원)
무료로도 쓸 만해야 하니, 유료는 **깊이**로 나눕니다.
- 7일 → 15일 전망
- 즐겨찾기 포인트 조건 충족 시 알림 (예: "영흥도 이번 주 목요일 밤 조건 최상")
- 시간별 상세 (지금 무료는 시간창 하나만)
- 조과 기록 무제한·통계
- 광고 제거

낚시 인구는 지출을 아끼지 않는 편입니다. 채비 하나가 구독료 1년치입니다.

### ③ 지역 상권 연결 (광고보다 이게 낫습니다)
"영흥도 21:49 진입" 결론 아래에 붙는 것들:
- 근처 낚시점 (미끼·채비, 야간 영업 여부)
- 갯벌 근처 숙박·주차
- 조개 삶아주는 식당

배너 광고가 아니라 **정보로 붙입니다.** "이 시간에 여는 낚시점" 은 광고가 아니라 필요한 정보입니다.
정액 등록비(월 3~5만원)나 통화 연결 건당 과금이 맞습니다.

> 참고로 석모도에서 숙박업을 하고 계시니, 강화·석모도 권역은 직접 시험해보기 좋습니다.
> 해루질 손님이 실제로 어떤 정보를 아쉬워하는지 바로 들을 수 있는 자리입니다.

### ④ 장비 제휴 판매
결론 화면에서 준비물을 이미 말하고 있습니다 — 랜턴, 갯벌화, 호미, 채집망.
"오늘 시야 40cm" 라고 알려준 다음 방수 랜턴을 붙이는 건 광고가 아니라 이어지는 말입니다.
초기에는 쿠팡파트너스 같은 제휴 링크로 시작하고, 거래가 쌓이면 직접 매입도 가능합니다.

### ⑤ 유튜버 레퍼럴 수익분배 (요청하신 것 — 코드 훅까지 이미 심어둠)

**왜 맞는 방향인가.** 해루질·낚시 유입은 검색이 아니라 유튜브에서 옵니다.
조황 영상의 고정댓글에 "오늘 이 포인트 물때 점수 보기 → 앱주소?ref=채널코드" 한 줄이면
영상(어제의 조황)과 앱(오늘의 조건)이 서로를 보완합니다. 유튜버는 영상마다 새 소재가 생기고, 앱은 광고비 없이 옵니다.

**동작 방식 (이미 구현됨)**

```
앱주소?ref=haeru_tv 로 접속
→ 30일 귀속 창으로 기기에 저장 (라스트터치 — 나중에 들어온 코드가 이김)
→ 방문·상세열람·길찾기 전환이 채널코드별로 집계됨
→ 앱스 스크립트에서 refStats() 실행하면 파트너별 표가 나옴
```

**분배 알고리즘 제안**

| 항목 | 내용 |
|---|---|
| 정산 대상 | 귀속 사용자가 만든 수익 — 구독료는 첫 12개월분, 예약·제휴 수수료는 건별 |
| 기본 분배율 | 대상 수익의 30% |
| 등급 가산 | 월 신규 귀속 100명 이상 35%, 1,000명 이상 40% |
| 예약 중개 | 플랫폼 수수료의 20% (마진이 얇아 별도 요율) |
| 정산 주기 | 월 1회, 집계표를 파트너에게 그대로 공개 |

**부정 방지 (알고리즘에 반드시 포함)**
- 같은 기기 반복 방문은 1회로 집계 (기기 저장소 기준)
- 방문만 있고 전환(상세열람·길찾기·예약)이 0인 코드는 정산 제외 — 봇 유입 차단
- 파트너 본인 결제는 정산 제외
- 분쟁 대비: 집계 원본(refStats)을 양쪽이 같은 화면으로 봄

**순서.** 지금은 유입 집계만 돌린다(수익원이 아직 없으므로). 구독·예약이 붙는 순간
같은 집계에 금액만 실으면 정산이 된다 — `trackRef_(코드, 'conv', 금액)` 한 줄이 그 자리다.
수익분배 약정은 반드시 서면으로 하고, 사업자 간 세금계산서 처리가 필요하다.

### ⑥ 데이터 판매 — 장기
조과·방문 데이터가 쌓이면 지자체·수산 연구기관·어촌계가 살 만한 것이 됩니다.
개인정보를 빼고 집계 수준으로만. 다만 **사용자 신뢰를 깎으면 안 되니 마지막**입니다.

### ⑦ 광고 (말씀하신 것 — 마지막에 두는 이유)
일반 배너는 단가가 낮고(월 수십만원 수준) 앱 인상을 크게 해칩니다.
넣더라도 **원픽 카드 아래 한 자리, 지역·시즌이 맞는 것만** 으로 제한하는 게 좋습니다.
같은 자리를 ③번 지역 상권에 팔면 단가가 몇 배입니다.

## 3. 넣지 말아야 할 것

- **안전 정보를 유료로 가리는 것** — 파고·금어기 경고는 무조건 무료여야 합니다. 사고가 나면 앱이 끝납니다.
- **금어기 대상 어종 광고** — 법 위반을 부추기는 모양이 됩니다. 어종별 광고는 금어기 필터를 반드시 통과시키세요.
- **조황 과장** — 점수를 부풀리면 한 번은 오지만 두 번은 안 옵니다. 지금 안전 게이트를 넣은 이유와 같습니다.

---

## 4. 순서 제안

```
1차 (지금)      무료 앱으로 사용자 확보 · 조황 기록 기능
2차 (3~6개월)   지역 상권 등록 + 장비 제휴 링크
3차 (6~12개월)  낚싯배 예약 중개 — 서해 한 권역부터 시험
4차 (12개월~)   구독 도입 · 예약 전국 확대
```

**낚싯배 예약을 1차에 넣지 않는 이유:** 선주 확보가 영업이지 개발이 아닙니다.
사용자가 먼저 모여 있어야 선주가 붙습니다. 반대로 하면 양쪽 다 안 모입니다.

## 5. 지금 코드에 미리 심어둘 것

수익화를 나중에 붙이더라도, 지금 데이터 구조에 자리만 만들어두면 나중이 편합니다.

- 포인트마다 `fr`(출항지·소요시간)이 이미 있음 → **예약 연결 자리 확보됨**
- 포인트마다 `r`(행정구역) 있음 → **지역 상권 매칭 가능**
- 대상물마다 금어기 판정 있음 → **광고 필터링 근거 확보됨**
- 조과 기록용 스프레드시트 연동만 추가하면 됨 → 앱스 스크립트라 시트 연결이 쉽습니다

추가로 심어둘 것을 제안합니다.
- 포인트에 `shop:[]` (근처 상점), `stay:[]` (숙박) 빈 배열
- 사용자 식별자 하나 (구글 로그인이면 이메일 해시)
- 화면 진입·클릭 로그를 시트에 남기는 함수 — 나중에 어느 자리가 값어치 있는지 판단할 근거
